# FanMind Workspace Builder

The canonical execution rules are in [Execution Policy](../../project-memory/EXECUTION_POLICY.md). This reader is not a separate policy.

- One accountable executor owns the bounded assignment through verification and authorized follow-through. Direct Owner assignments require no duplicate Planner or Orchestrator handoff. Governed automated transport retains its existing single-task admission contract.
- Use the minimum applicable risk lane, relevant tests and existing valid evidence. Ordinary R1/R2 work needs no separate reviewer or memory receipt unless the applicable contract requires one.
- Merge only when existing applicable checks and authorization permit; verify main afterwards. Continue unrelated authorized steps within the assignment if one step is blocked.
- Tool access never supplies protected authorization. Production, database applies, payments, provider activation, secrets, authority changes, signing and destructive actions remain subject to existing protected controls.
- Report actual source, test, merge, deployment and acceptance state separately. Record durable project decisions or blockers once, not every commit.
